# ベースライン KPI マップ（GSC / GA4）

## 目的

主要キーワードとランディングページの対応を固定し、週次で平均順位・表示回数・クリック・TOP10流入・LP別CVを追跡する。

## 主要KWクラスタ（計画どおり）

| クラスタ | 代表クエリ例 | 主なランディング（想定） |
|----------|--------------|-------------------------|
| 手続き | 改葬許可申請書、書き方、提出先 | `/kaisoukyoka`, `/flow`, 市区町村ページ |
| 費用 | 墓じまい 費用、相場、内訳 | `/price`, `/` |
| 地域 | {市区町村} 改葬 申請 | `/kaissou/{pref}/{muni}` |
| 比較・意思決定 | 散骨、永代供養、納骨堂 | `/kaissou`, `/sankotsu`, `/kaisougo` 等 |

## GSC でのセットアップ

1. **プロパティ**: 本番は `https://www.ohakajimai-navi.jp` をcanonical参照と揃える。
2. **期間**: ベースラインは「施策前」の同一期間長（例: 過去28日）でスナップショット。
3. **エクスポート**:
   - 検索パフォーマンス → クエリ（フィルタ: 上表クラスタに合致する語をタグ付け）。
   - 検索パフォーマンス → ページ（`/`, `/kaissou`, `/kaisoukyoka`, `/flow`, `/price`、および `/kaissou/` 配下）。
4. **マッピング表**（スプレッドシート推奨列）:

   - `query`, `landing_page_url`, `impressions`, `clicks`, `ctr`, `position`, `week_label`

## GA4 でのセットアップ

1. **ディメンション**: ページパス、アウトバウンド先（クロスドメインは `noopener noreferrer` 前提でも、イベントでコンテキスト付与）。
2. **転換イベント**（例）:

   - お問い合わせ送信
   - 見積・相談系の送信完了

3. **探索レポート**: LP別セッション・アウトバウンド（清蓮グループサイト）を `イベントパラメータ` でコンテキスト分離する（計画書「どのコンテキストからの送客か」）。

## 運用ルール

- 週次: クエリ×LP を更新し、「位置づけの変化」をメモには残さず表にのみ残さないこと（変更理由も1行）。
- メタ／構造化データを変えた週は、**同じクエリセット**で前週比を必ず見る。
- KPIの一次ソースは **GSC + GA4** とし、他ツールは補助に留める。

## 完了判定（フェーズ1）

- 主要KW一覧と対応LP一覧がドラフトなく確定している。
- 少なくとも1サイクルの数値がスナップショットとして保存されている（以降の伸長の基準）。
