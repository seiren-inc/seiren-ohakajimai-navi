# プレミアム Web 品質ゲート（TOP3 計画 §6）

本番における「最も綺麗な Web」レベルの品質は、**大規模なレイアウト変更**ではなくプロジェクト規約（テクスチャトークン・タイポ・アクセシビリティ・パフォーマンス・アニメ規律）を満たすことで定義する。**レイアウト／余白／コンポーネント構成の変更はスコープ単位で明示承認**すること（プロジェクト `AGENTS.md` の UI Protection と整合）。

> **自動ゲートとの違い**  
> `npm run quality:gate` は自治体データ・リンク・インポートなどの **データ／SEO インテグリティ** 向けゲートであり、ここでの「プレミアム Web」ゲートとは別物。このドキュメントは **視覚トークン・UX・CWV・ア11y・アニメ** を前提とした **人的チェックリスト＋検証ツール手順** である。

## 1. 視覚・トーン（Texture Token）

- 主要ページ背景・広いサーフェスに `var(--texture-paper)` または `var(--texture-clay)` を優先している（フラット単色のみの広い塗りに逃げていない）。
- 境界・強い線は `var(--color-mineral)` を使い、単体のフラット HEX だけでの置き換えをしていない。
- 「装飾用」にフラット HEX の大面積ボタン背景を増やしていない（CTA は既存のデザインシステムコンポーネントに準拠）。

## 2. タイポグラフィ・リズム

- `CLAUDE.md` どおりフォントファミリーは変更していない（Noto Serif JP `--font-serif` / Noto Sans JP `--font-sans`）。
- 見出し階層（`h1`→`h2`→…）がページ内で論理的。**1ページ 1 `h1`**。
- 本文段落の読みやすさ（適度な行長・段落間隔）を維持。新規コピーだけが極端に密集していない。
- prose クラス利用時も、サイト全体トーンとの齟齬がないこと。

## 3. アクセシビリティ（WCAG 2.2 を意識）

- **キーボード**: 主要フォーム・ヘッダー・モーダル・フッターリンクが Tab で到達可能。
- **フォーカス**: 視認できるフォーカスリングが消されていない（`outline-none` だけにしていない）。
- **画像**: 意味のある画像に適切な `alt`。装飾画像は空 alt または隠匿が妥当か確認。
- **フォーム**: ラベル紐付け、エラー文言、必須表示が一貫。
- `**prefers-reduced-motion`**: 新規に追加した強いモーション・アニメに、必要に応じた配慮がある（既存サイト方針に合わせる）。

**自動化のひとかたまり**: `npm run lint` は `eslint-config-next`（Core Web Vitals）経由で **一部の jsx-a11y ルール** を含む。これを **最低ライン** とし、このチェックリストで **自動では拾えない行為** をカバーする。

## 4. パフォーマンス（CWV・アニメ過剰回避）

- **LCP**: ヒーロー画像が過大サイズ／遅延不要な遅読み込みになっていない。
- **CLS**: フォント・アニメ・遅延埋め込みでレイアウトが大きく飛んでいない。
- **INP**: メイン画面上のイベントハンドラが不必要に重くなっていない（大量のスクロール連結アニメ等を避ける）。
- **JS**: `use client` 範囲を必要最小限に保っている（新規でページ全体クライアント化していない）。
- Three.js は **規約どおり動的 import + `ssr: false` + Suspense**。

**コマンド例**（ローカルで dev または `npm run build && npm run start` 後）:

```bash
npm run verify:perf
```

Lighthouse がローカルの `http://localhost:3000` を見る既定のため、**代表 URL を回すときは Lighthouse CLI の `--url` を複数指定**するか、同コマンドを URL ごとに繰り返す。

参考しきい値（Google CWV 「良好」の目安）:


| メトリック | 目安（モバイル） |
| ----- | -------- |
| LCP   | ≤ 2.5 s  |
| INP   | ≤ 200 ms |
| CLS   | ≤ 0.1    |


閾値未達時は **まずコンテンツ／画像／クライアント境界** を疑い、安易な全ページレイアウト変更はしない。

## 5. UX（読み進めやすさ・モバイル）

- 主要 CTA と本文リンクの **タップ領域** がモバイルで十分。
- 「次に読むべきページ」が文脈で示されている（内部リンク過多にならない範囲）。
- 読み込み・エラー・空状態のコピーが主要フローで分かりやすい。
- **エコシステム外向けリンク**: 別ドメインであること／情報とサービス提案の境界がユーザーに伝わる（関連: `docs/seo/seiren-ecosystem-ia.md`）。

## 6. PASS（スプリント受け入れ）

次を **すべて満たせば** そのスプリントの「プレミアム品質ゲート」PASS とする。

1. 上記 **§1〜5 のチェック**を、今回変更したページおよび **§7 代表 URL のうちローテーション対象 URL** で実施済みであること。
2. `npm run verify` が成功すること（Lint + Typecheck）。
3. 代表 URL に対して **Lighthouse を少なくとも 1 URL** で実行し、結果をスプリント証跡として残す（スクリーンショットまたは JSON ログの保存はチーム運用に従う）。
4. 大規模 UI 変更を含む場合は **事前承認済みスコープ** 内であること。

## 8. スキル・レビューの使いどころ

- **定期的なレビューやコンポーネント追加後**: プロジェクト内 `.claude/skills/ui-qa-check/SKILL.md`（デザインシステム・モバイルファースト・文言）を、スプリント末に選択利用できる。
- **重大な視覚リグレッション懸念**: 必要に応じ **Playwright スクリーンショット** またはステージングの目視確認を同一ゲートに含める。

## 9. 退行禁止

変更は **コンテンツ品質／指摘バグ修正／承認済みデザインスコープ** に限定する。「プレミアム刷新」だけを目的とした横断レイアウト変更は、別フェーズ・別承認とする。
