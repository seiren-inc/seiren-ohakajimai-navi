# Implementation Rules

## Default Approach

Use the smallest safe diff.

Preserve the existing implementation unless the task clearly requires change.

## Before Code Changes

Check:

- Existing route
- Existing component
- Existing data source
- Existing style pattern
- Existing SEO behavior
- Existing validation command

## Do Not

- Do not rewrite whole files unnecessarily
- Do not change unrelated components
- Do not reformat large files
- Do not introduce new architecture without approval
- Do not change database schema without plan
- Do not change public data shape without plan

## UI Changes

When changing UI:

- Preserve responsive behavior
- Preserve accessibility
- Preserve semantic HTML
- Preserve CTA behavior
- Preserve metadata
- Avoid layout shift
